# Self-improvement lessons

Use a tight loop: inspect → propose → execute → evaluate → repair → promote.
One task has one owner, one observable improvement, and one smallest credible
verification command.

Safe autonomy covers scoped local edits, tests, and disposable `/tmp` output.
Destructive cleanup, broad contract changes, production synthesis/rendering,
commits, pushes, and external communication need explicit authorization unless
the user authorizes an unattended bounded run.

Resume from the last verified receipt after interruption. Failed evaluation
creates repair work; it is never success. Human review is preferred for visual
judgment and release decisions.

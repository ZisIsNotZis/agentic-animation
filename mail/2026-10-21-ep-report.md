## The seam was one line, and it was not where the report guessed

The measured refusals reproduce exactly, in the package's own fixture:

- native receiver at x 1400, beat 2.04 → `whole-body proposal exhausted:
  receiver at 2.275s; palm-contact/hand_r NaN > 0.020`
- two native actors (any staged distance tried) → the same receiver refusal
  first; E2's `foot-reach/foot_r Infinity` is the same cascade seen on the other
  actor.

Chain, verified by instrumenting `validateState` and `advanceSupport`:

1. The **taut push arm** pulled its root with `nextX = state.x + dir*excess`,
   then clamped `nextX` against every other body regardless of which side that
   body was on. With the server at x 640 behind the receiver at x 1448.9, the
   clamp produced `nextX = 564.03` — **an 885 px backward teleport in one
   substep** (`root-rate` 884.894 > 6.000). The walk path already keeps this
   direction-of-travel rule ("a body behind the walker must not clamp"); the
   taut-arm drag did not.
2. The proposal refused the substep, so the stance feet never replanted while
   the (untaken) step demands moved the aim 890 px off the body.
3. `legDropInterval` returned `null` for that aim and `advanceSupport` wrote
   `supportMinimum = Infinity` into a numeric posture; `crouch` followed it to
   Infinity, `pose.waistY` became Infinity, `solveSkeleton` returned Infinity at
   every joint and `solveReach`'s `rot(0, [-Infinity])` produced `0*Infinity =
   NaN` in the arm angles — which is why it surfaced as `palm-contact/hand_r
   NaN` on the receiver and `foot-reach/foot_r Infinity` on the server.

So the class the docs named (annulus boundary / zero-slack rest legs) was the
second half, not the cause: the non-finite came from a stale support anchor, and
it read as a tolerance failure because it reached the checks as a measured
distance. Both halves are fixed, neither by widening anything.

## The fix, at the smallest seams

`packages/core/src/motor/index.ts` (taut-arm drag): the root step is clamped
only against a body in the direction of travel — the walk's existing rule, now
kept here. Falsified: revert it and both native-pair tests fail again.

`packages/core/src/motor/wholeBodyProposal.ts`:

- `foot-reach` compares like with like **at the clamp**: the drawn foot against
  the foot the motor's own `plantedLegAngles` solve *lands* for that aim (same
  solver, same FK), never against a point that sits on the reachable annulus
  boundary. `leg-annulus` keeps owning reachability, so an unreachable aim is
  reported once, as reachability, and not twice as a sub-pixel shortfall. The
  check still catches a pose whose drawn leg is not the leg its aim solves.
- A non-finite foot target, palm target or hip drop is refused by
  `foot-target-non-finite` / `palm-target-non-finite` / `waist-drop-non-finite`,
  naming the joint, carrying the offending value — instead of a NaN ratio that
  reads as a tolerance miss on a substep nobody could have solved.

No tolerance widened (`.02`, `.5`, `720`, `840` untouched), no rate gate
relaxed, no exemption list. `footTargets`/`palmTarget` semantics unchanged.

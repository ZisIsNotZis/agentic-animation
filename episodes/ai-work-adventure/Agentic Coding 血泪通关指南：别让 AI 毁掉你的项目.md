# Agentic Coding 血泪通关指南：别让 AI 毁掉你的项目

**分享定位**：面向实战派 Agent 开发者，无鸡汤、纯血泪踩坑总结。帮助大家从「瞎用 AI 越用越崩」升级为「人定规则、Agent 托管、渐进解放」。

**核心主旨**：AI 从来不是全自动躺平外挂，而是需要人类驯化、约束、调度的高级工程工人。Agentic Coding 的核心本质，不是单纯让 AI 代写代码，而是**人类掌控架构、规则、决策、唯一真相源，Agent 全权承接所有机械、重复、迭代的脏活累活**。真正的人力解放，来自标准化的工程流程与规则约束，而非无脑依赖模型能力，最终实现渐进式解放，杜绝摆烂式翻车。

## 开篇：为什么 90% 的人用 Agent 写代码越用越崩？

很多开发者的现状：开 AI 一通狂敲指令，初期写得飞快，后期 Bug 成堆、账单爆炸、代码越写越乱、AI 反复失忆、重构直接毁项目。

所有 Agent 翻车问题，归根结底只有三类，吃透这三点，就吃透了 80% 的避坑逻辑：

1. **人的问题**：需求模糊、没有设计、规则不清、瞎指挥，把自己的懒惰甩给 AI

2. **工作流问题**：记忆污染、上下文炸掉、技能不触发、模型和工具不匹配、缓存失效

3. **模型硬上限**：部分复杂逻辑、隐性工程经验，再强的 AI 也无法自主顿悟

真正的 Agent 高手，从来不是会写 prompt，而是**会立规则、会控流程、会堵漏洞、会懂取舍**。

**核心工具锚点**：/wayfinder（全局规划）、/grill\-me（自我拷问纠错）、/colleague\-skill（能力蒸馏）、/code\-review（独立审查）、/handoff（模型切换）、/writing\-for\-agents（Agent 友好文档）、/skill\-creator（技能定制）、/ask\-matt（流程导航\&经验蒸馏）、caveman（输入输出缓存）

## 第一章：破除最大误区——不是 AI 蠢，是你不会「驯化」

很多人吐槽 AI 智商不稳定、写代码不合心意，本质是**你只给了任务，没给人设、规则、审美和底线**。AI 没有自主审美，没有你的工程哲学，只会复刻你的指令。

### 1\.1 自我蒸馏：把你的能力变成 Agent 的标配技能

用 /colleague\-skill 蒸馏自己的编码习惯、工程规范、纠错逻辑。不要指望 AI 天生懂你的风格，你不教，它就随机发挥。

### 1\.2 明确你的工程哲学，拒绝 AI 自由发挥

编码偏好、架构思路、容错原则、取舍逻辑，必须显性告知 AI。模糊的默认认知，是 Agent 翻车的第一元凶。

### 1\.3 技能匹配要精准，且必须主动调用

可以安装适配项目的专属技能库，也可通过 **/findskill** 让 AI 自主检索、匹配当前任务所需技能，但**绝对不要迷信 Skill**。随着大模型原生能力持续迭代，绝大多数基础性 Skill（如 superpowers、Everything Claude Code/ECC）的边际价值正在持续降低。这类 Skill 自带的 Hook 强制检查属于锦上添花的兜底能力，有一定辅助作用，但本体功能已经越来越冗余——现阶段主流模型本身原生能力极强，各类 Agent 框架也默认搭载了大量内置基础能力，完全无需靠额外基础 Skill 兜底。

当下 Skill 的真正价值，只集中在**模型原生缺失的流程性、小众垂直领域**：比如 Matt 标准化软件工程工作流、Hyperframes/Remotion 文本生图文视频能力、SD 系列生图技能、前端审美与精细化布局专项能力等。除此之外，绝大多数通用 Skill 都没必要堆砌。

最重要的血泪认知：**Skill 本身是负担，更是安全风险**。Skill 会占用上下文 Token、增加模型适配负担、拉高会话复杂度；更致命的是，恶意 Skill 可直接植入木马、窃取信息、篡改代码，存在极高安全隐患。Skill 配置遵循「按需极简」原则：**可以有，但必须针对性匹配场景，绝对不是越多越好**。

### 1\.4 不用过度纠结基础安全

不用过度纠结基础安全、代码风格这类基础问题！现代大模型基础能力已经极度成熟，常规格式规范、基础语法错误、简易安全漏洞，AI 基本不会出错。即便有疏漏，后续 /code\-review 独立审查也能兜底，不用人类逐行盯细节，解放琐碎精力。

## 第二章：根治 AI 健忘症——搭建永不失效的「项目记忆系统」

AI 健忘从来不是记忆力差，是**你没给它搭建永久记忆，全靠临时上下文兜底**。上下文会刷新、会压缩、会丢失，只有文档和规则是永恒的。

### 2\.1 双层 AGENTS\.md 规则体系（强制规范）

- **全局 AGENTS\.md**：存放通用编码规范、全局审美、通用工具使用规则，适配所有项目

- **项目本地 AGENTS\.md**：存放当前项目专属架构、文件约定、业务约束、权限规则

- **最高优先级铁律**：本地规则 \> 全局规则；任何场景下，**代码变更前必须优先更新文档**，无例外、无变通，该规则已固化进项目 Agent 规则

### 2\.2 标准化项目记忆目录，拒绝信息杂乱

开启新项目的核心第一件事，不是写代码，而是**搭建结构化文档体系**，无需死板堆砌目录，按需搭建核心文档目录、建立信息分层规则即可，核心保留三类关键目录，各司其职、守住项目记忆底线：

- docs/：唯一真相源，正式、权威、不可私自篡改

- wiki/：项目知识库、问题沉淀、方案记录

- design/：架构设计、接口定义、技术方案

### 2\.3 Agent 专属文档写法：拒绝流水账

给 AI 看的文档，不是人类随笔！必须结构化、高密度、无废话，**单文件绝不超过 200 行**。流水账文档只会让 AI 提取关键信息失败，变相造成“健忘”。

工具赋能：用 /writing\-for\-agents 生成标准化文档，用 /skill\-creator 固化文档使用规则，让 AI 精准读懂、严格执行。

### 2\.4 主从 Agent 分工：别让主 Agent 干脏活

主 Agent 只做**调度、规划、决策、理解你的需求**，所有编码、改代码、测试、文档编辑等实操工作，全部丢给子 Agent。

核心避坑：避免主 Agent 上下文被垃圾信息填满，导致核心决策失忆、判断力下降。

### 2\.5 终极原则：单一信息源，杜绝文档漂移

一条信息只存在一个位置，无重复、无冲突、无冗余。**核心关键：文档不是平铺的记事本，是一棵互相关联、互相锚定的树形结构**。所有需求变更、方案妥协、临时 workaround，绝对不能简单 append 追加新内容、只改单段文本。单次变更必须**修改原有对应节点 \+ 同步更新所有关联链路、关联文档、交叉引用**，彻底杜绝局部修改导致的文档内部逻辑割裂、信息不一致。严格遵守铁律：**先全链路更新文档、写清变更原因与取舍逻辑，再动手改代码**。人类只改代码、不同步迭代整套文档树，是所有项目架构腐化、后期彻底烂尾的核心根源。

## 第三章：根治账单爆炸——低成本、高性价比 Agent 调度心法

大部分人 Token 超标，不是写代码太多，是**无效重试、重复加载、频繁改配置、反复返工**造成的隐形消耗。

### 3\.1 高低配模型分层，极致性价比

- 高智商旗舰模型：只做顶层规划、方案评审、复杂决策、精准提示词生成

- 中低端廉价模型：全权负责编码、测试、修改、格式化等重复实操工作

### 3\.2 缓存是省钱核心，千万别乱改配置

不要在任务中途随意更换工具、MCP、技能集合！每次配置变更都会直接清空缓存、触发全量重计算，Token 消耗直接翻倍，这是无数人账单爆炸的隐形元凶。

### 3\.3 深坑预警：Caveman 不要无脑开，收益极低且暗藏副作用

很多人把 caveman 当做省钱神器，**实际中短期会话里基本负收益**，必须严格区分 Caveman Skill（输出保存）与 Caveman Engine（输入缓存），二者都有致命坑点：

**1）Caveman Skill（节省输出）：中短期 Session 基本无用，纯亏 Token**
AI 最贵的开销从来是 **Reasoning 思考 Token**，而非最终输出文本。Skill 完全省不下推理成本，反而会新增巨额开销：Skill 自身加载常驻占用 **1000\+ Token**，还会让模型额外消耗思考算力，适配其输出规约、格式约束，甚至刻意调整表达范式，变相拉长推理链路，越开越费。

**2）Caveman Engine（节省输入）：会隐性降智，破坏输出质量**
输入缓存看似减少重复文档投喂，但其压缩、切片、缓存重组逻辑，会**破坏模型原生输出状态分布**，打乱上下文语义连贯性，导致模型理解偏差、逻辑断层、细节丢失，直观表现就是 AI 莫名变蠢、逻辑飘移、细节翻车。

**实战结论**：绝大多数日常开发、中短期迭代 Session，**建议直接关闭 caveman**。仅超长期、超大上下文、大批量重复输出的专属任务，才有可能微弱回本，普通场景属于典型「捡芝麻、丢西瓜」。

### 3\.4 模型引擎取舍血泪经验：成本、限速、隐式丐版全避坑

不同调用引擎没有绝对好坏，只有**成本与稳定性的残酷取舍**，绝大多数账单翻车、突然炸车、质量暴跌，都是选错引擎导致：

- **Coding Plan / 第三方引擎（火山引擎等）**：极致便宜、成本碾压原生 API，是批量机械干活的性价比首选。但致命短板极其明显：服务质量不稳定、常态化限速、突发 429 限流拒绝服务、高峰期直接打不通，需要主动暂停等待恢复，非常影响连续开发节奏。

- **原生官方 Token API**：无硬性小时额度、无频繁限流、响应稳定、速度更快，开发体验丝滑，但单价更高，长期高频使用账单压力更大。

- **模型快速模式**：提速明显，但 Token 消耗 1\.5 倍，适合紧急赶工，不适合常态使用。

**第三方引擎最大隐形深坑（99% 人踩坑）：默认全是丐版**
不要迷信第三方标注的模型名，没明确写全参数、精度的，一律按缩水丐版对待：

- 例如 Qwen3\.5，未标注规格默认是 35B\-A3B 小参版，而非满血 200B\+ 版本

- 即使标注满血，默认多为 Q4 低精度量化，而非 FP8 高精度版本，推理细节、逻辑严谨性、长文本稳定性都会明显降级

**原生 API 省钱实战技巧：错峰避峰**
官方模型存在明显峰谷价差与流量拥堵，白天高峰期不仅贵、还容易排队降速、隐性限流。日常在家开发可以反向作息：**高峰期停手休息，低谷时段集中批量跑任务**，既能省钱，又能规避官方流量拥堵导致的随机降智、超时、重试炸 Token。

**最终取舍铁律**：简单机械迭代、大批量重复任务、不抠极致质量 → 用便宜第三方引擎；核心方案评审、复杂逻辑推理、关键代码生成、长链路任务 → 必须上原生满血 API，别为省钱翻车返工。

### 3\.5 隐藏深坑：自动压缩=隐形烧钱

绝大多数人依赖自动上下文压缩、长期会话续连省钱，属于典型「短期微利、长期巨亏」。**Session 上下文本身就是最高风险存储**：Agent 窗口崩溃、会话丢失、Resume 失败、Resume 回退旧版本，都会让你投入海量 Token 推理出的架构结论、取舍逻辑、踩坑经验直接清零。更致命的是团队交接：无固化文档 = 新人完整重踩所有旧坑。

另外一个隐形大坑：**会话指令残留污染**。废弃指令、失败计划、旧追问会隐性驻留上下文，让模型左右兼容、逻辑分裂，越写越飘。重大迭代务必开新 Session，不要恋栈旧会话垃圾。

唯一工程解：**所有高价值信息、QuickStart、已知问题、Roadmap、架构约束，全部沉淀树形文档**。不靠会话兜底，只靠结构化文档永久确权。

## 第四章：告别项目越做越烂——Agent 开发的工程铁律

很多项目从雏形变成烂尾屎山，全是因为用人类随性编码思维，指挥严谨的 Agent 开发。Agent 不会帮你兜底，你的每一个随性操作，都会变成未来的 Bug 和债务。

### 4\.1 先规划后执行，拒绝即兴开发

Agent 开发核心铁律：**信息一次性完整披露，实现渐进落地；文档全量前置且持续最新，实现代码增量迭代**。能一次性讲清的需求、边界、架构约束、取舍逻辑，绝不分批追加。依托 /wayfinder 全局建模、/grill\-me 反向拷问，提前消灭模糊点与矛盾点。

绝大多数返工源于「信息披露不完整、文档滞后于代码」。禁止自上而下空泛架构拍板，也禁止边写边补需求。文档是**树形关联体系**，更新不是简单追加内容，必须联动所有关联节点、引用、约束，保证全局一致性，杜绝局部修改导致的逻辑割裂。

### 4\.2 严禁 AI 全域重构，这是顶级毁项目操作

AI 全域重构是顶级毁项目操作。模型会无差别覆盖正确逻辑、隐性契约、边界容错，产出新旧混杂的“半重构屎山”，债务比完全重写更难修复。实操规则：只允许增量修改，大规模重构必须交给独立子 Agent，全程人工 Diff 校验。

实操规则：只允许增量修改，大规模重构必须交给独立子 Agent，且全程人工校验 diff。

### 4\.3 禁止提前抽象，无用抽象就是纯浪费

没有足够业务迭代经验，所有提前抽象都是自作聪明。只会浪费 Token、增加代码复杂度、拖慢开发进度，毫无正向价值。

### 4\.4 垂直切片开发：唯一靠谱的 Agent 迭代模式

标准流程：设计文档 → 原型草稿 → 最小可用 v1 → 迭代优化。先跑通完整业务链路，再优化细节，拒绝碎片化开发。

### 4\.5 最简原则：无代码 \> 少代码 \> 多代码

坚守核心工程原则：**无代码 \> 少代码 \> 多代码**。不要迷信 AI 能从零造轮子，也不要纵容 AI 迭代出复杂伪需求、过度设计。可以借助 **/ponytail** 工具辅助自我审视、需求瘦身，主动砍掉多余功能、冗余设计、麻烦的伪需求。AI 造轮子、瞎迭代非标需求不仅耗时耗 Token，还会堆积大量隐性 Bug，远不如复用成熟开源方案、做极简刚需落地靠谱。

### 4\.6 善用官方工具，拒绝盲目全自动

/goal、/plan、/loop 等标准化工具是兜底神器。模型会随机降智、抽风，不要赌 AI 全程稳定，用工具锁住流程，规避随机翻车。

## 第五章：根治 Bug 泛滥——多层级 Agent 质量闭环体系

AI 写的代码，天生自带“假性正确”，看着能跑、全是隐性坑。想要低 Bug，必须搭建**多层校验、互相制衡**的质检体系。

### 5\.1 前置校验：方案评审大于代码纠错

所有开发前，先评审方案完整性、边界场景、异常处理。方案错了，代码写得再完美也是废品。

### 5\.2 强制 TDD 测试驱动，不要默认 AI 懂严谨性

必须显性要求 AI 执行 TDD，涵盖单元测试、接口测试、E2E 全链路测试，同时搭配**低分辨率视觉抽检**，这是性价比极高的质检手段。480p、720p 这类中低分辨率图像检测，仅需 100\~几百个 Token，成本微乎其微。对比后续人工排查问题、文字描述缺陷、引导 AI 反复返工，还大概率描述不清、修复不彻底的高额时间与算力成本，这少量 Token 开销完全值得，能提前堵死绝大多数界面、样式、显性展示类隐性 Bug。

核心坑点：AI 生成测试普遍存在空断言、弱覆盖、假通过问题，**测试通过≠功能正确**，绝对不能无脑信任。

### 5\.3 独立第三方 Code Review，拒绝自审自判

严禁编码 Agent 自审自查，自身存在极强思维偏见，根本无法发现内生漏洞，必须 spawn 独立第三方审查子Agent 做隔离评审。这里补充一个非常真实的实战认知：**正式合规项目可以保留人工 Code Review 流程，但绝大多数短期个人/小团队项目，人工 Review 基本是自我欺骗**。很多时候 AI 产出的代码技术栈偏冷门、逻辑复杂，我们自己其实根本看不懂，只是假装看过、草草过关。与其硬撑无效自查，不如务实兜底：**放弃低效人类逐行审码，强制让 AI 把代码讲明白**，搭配 **/bro、/eli5（小白式通俗解读）** 拆解逻辑、风险、适用边界，远比自我感动式 Review 更加靠谱、真实有效。

### 5\.4 强制溯源：让 AI 解释每一段代码

写完代码必须追问：这段代码的作用、适用场景、已知风险、边界短板。逼出隐性问题，避免埋雷。

### 5\.5 人机双测：AI 校验 \+ 人工用户视角测试

AI 只能校验代码逻辑，无法感知用户体验、业务合理性。必须自己上手当用户，实测功能，补齐 AI 的认知盲区。

### 5\.6 灰度发布 \+ 分级问题处理

## 第七章：极易被忽略的隐形深坑（血泪补充）

这些坑 99% 的开发者都踩过，且网上几乎没有完整总结，是高手和新手的核心差距。

### 7\.1 Agent 与 Git 的博弈：人控版本，Agent 改代码

### 7\.2 权限安全大坑：不要给 Agent 无上限权限

Auto Mode 仅适配官方高阶模型，非官方引擎易风控失效；存在漏报概率，不可完全替代人工兜底，且会小幅增加推理 Token 消耗。

### 7\.3 人的认知负荷陷阱：Agent 是减负，不是加负

Agentic Coding 不是全自动躺平！你依然需要审核规划、校验文档、排查 Bug、纠正 Agent 错误。**极小修改直接手写，复杂项目再上 Agent 工作流**，别杀鸡用牛刀，徒增负担。

### 7\.4 长期记忆污染坑

长期记忆不是越多越好！陈旧方案、废弃代码、错误试错记录不清理，会持续干扰 AI 判断，导致输出错乱，必须定期归档、清理无效记忆。
